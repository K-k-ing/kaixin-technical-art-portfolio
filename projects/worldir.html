01 / 研究问题

视觉可信，不等于空间可靠。

世界模型可以解释“这是什么、在哪里、与什么有关”，但语义合理的场景，不一定拥有可靠的深度、尺寸、相机或最终生产几何。

我先测试 Astra 的场景理解与布局描述，再将结构化结果编译成可编辑的 Unreal Actor，并用对象级 SpatialPatch 调整局部布局。

单视角歧义和空间漂移让我开始把模型建议、重建证据、人工接受的场景决策与程序执行分开。模型提供候选，而不是直接替最终场景决定一切。

系统方向 · 以下流程包含已实现、开发中与方案设计阶段

  1. 输入参考 / 世界输入
  2. 理解世界模型与空间证据
  3. 开发中Scene Graph记录已接受的决策、来源与未知
  4. 方案设计资产解析 / 候选替换
  5. 局部已实现场景编译
  6. 执行与检查Blender / Unreal Engine

模型提出候选，Scene Graph 记录决策，Compiler 执行。
Scene Graph 不会凭空补充缺失的证据，编译器也不应该虚构未知的空间事实。

02 / 空间证据与查询 · 实验中

知道哪些点有支持，
也知道哪些地方不能回答。

Marble 的 Gaussian / PLY 重建提供视觉与空间线索。我围绕相机投影、注册与源坐标查询开展实验，而不是将重建结果直接视为可靠的生产资产。

早期 Gaussian 数据集50 万 splats

重建表示的规模，不是精度指标。

像素到三维查询测试17 / 20

17 个查询获得支持，3 个明确返回无支持；不是整个场景的准确率。

源坐标尚未标定为真实米制空间。遮挡、深度歧义、相机不确定性与缺失背面几何仍需要独立处理。

03 / 限定地板实例化 · 已实现

一个 Mesh，九次放置。
但不是九个“观测事实”。

在一个限定的地板案例中，我分别记录六个源数据观测位置与三个设计推断位置，并编译到 Blender，让九次放置共用同一份 Mesh 数据。

6 个观测位置

保留证据来源

记录源数据支持的放置，不让后来补出的视觉结果覆盖原始事实。

3 个设计推断位置

承认这是设计选择

推断保留独立来源，并明确不拥有几何真值的权威。

1 份共享 Mesh

确定性地执行决策

在限定案例中复用生产几何，而不是为每个放置重复生成一份模型。

这一结果证明的是地板案例中的决策记录与实例化编译，不代表通用 Scene Graph、完整 Asset Resolver 或任意场景自动生成已经完成。

04 / 资产拟合与重建诊断 · 实验中

重建结果，不等于生产几何。

好看的候选，也可能放不进去。

我测试将外部生成的椅子放入重建空间，围绕相机投影、位置、尺寸与形态检查拟合结果。资产外观与 Mesh 候选不直接决定世界空间的位置。

拟合后仍存在深度与靠背等局部误差，需要人工接受阈值。单个椅子的实验不能推广成通用、自动成功的资产替换服务。

WorldSculpt：从碎片输出，到连续表面的诊断。

早期 GLB 虽然能正常读取，却由大量不连通碎片组成。排查权重 key mismatch 与加载检查后，修复实验得到更连续的表面，但仍有薄片、裂缝与残留碎片。

WorldSculpt 是已封存的专项实验分支，未接入默认主流程。密集重建可以提供几何证据，但计算成本、薄结构、拓扑、UV 与生产材质仍限制其直接用于实时资产生产。

05 / 当前结果与能力边界

把进展讲清楚，
也把未知保留下来。

已实现
结构化 Unreal Actor 编译与局部 SpatialPatch；限定地板案例的观测 / 推断记录与共享 Mesh 实例化。
实验中
Astra 语义与布局基线、Gaussian / PLY 查询、相机注册、外部资产拟合，以及已封存的 WorldSculpt 修复实验。
开发中
通用 Scene Graph，以及独立实验阶段之间的整合。
方案设计
通用 Asset Resolver、自动 UV / PBR 生产处理与完整 Blender-to-Unreal 交付验收闭环。
未来方向
探索交互式、随观察持续生成的世界，以及从生成观察到结构化场景的连续流程。

WORLDIR × MATE / 后续衔接方向

WORLDIR 组织场景需求，
MATE 支持资产与材质迭代。

WORLDIR 研究场景层的空间证据与结构化决策，MATE 研究资产层的审核、绑定与可编辑表面迭代。二者目前是独立原型；自动需求交接与场景回流仍是后续方向，不是已经运行的端到端系统。
