01 / 为什么需要 WORLDIR

看起来成立，
还不够让制作继续。

早期 Astra 场景抓住了走廊、窗户与设备的关系，但近景设备的体积和遮挡偏离参考。制作时，这意味着通道可能被挤占，资产也无法只凭“看起来像”就直接复用。

另一类问题出现在重建里：地板局部缺失、表面变形。直接复制源几何会复制误差，凭外观补齐又会把未知包装成观测事实。深度、尺度、相机与遮挡补全的不确定性，需要成为明确的数据和决策。

WORLDIR 的切入点是把建议与接受的场景状态分开：先记录证据与候选，检查结构和来源约束，再执行获批决策。它是场景组织与编译原型，不是通用精确重建器。

理解 / 重建工具

提供空间与语义候选

Astra、Marble 等工具提供布局、关系、重建表示及线索，也可能输出结构化数据；可靠程度需要按来源检查。

资产生成工具

提供几何与外观候选

Tripo / Hyper3D、WorldSculpt 提供对象候选。外观完整，仍需检查朝向、尺寸与场景适配。

WORLDIR

组织决策并执行

保存来源与理由，隔离未接受候选，检查支持范围，将获批的场景决策编译成执行计划。

02 / 输入—决策—输出

先确认可以相信什么，
再决定场景里放什么。

这是职责链，不是所有阶段已一键连通的演示。早期实验接触真实参考、重建和生成资产；v2 当前用固定的合成输入验证接口与编译规则。

  1. 01 →

    参考 / 世界输出 / 候选资产

    图像支持语义和外观；源空间与候选几何各自记录来源。参考图本身不自动提供可靠 XYZ。

    早期：真实实验 · v2：合成 fixture
  2. 02 →

    Evidence & Proposals

    保留捕获的输入与提案。高置信度候选也不能跳过接受步骤，写入 canonical scene transform。

    v2 Core / 已实现、合成验证
  3. 03 →

    Validation + Explicit Decisions

    逐字段检查来源、选定值、理由与 revision。条件不足就保留 unknown 或 deferred。

    v2 Core / 已实现、合成验证
  4. 04 →

    Accepted Scene Graph

    记录已接受的结构与变换，以及对应证据和决策。v2 的 AcceptedGraph 以不可变 revision 保存。

    v2 Core / 已实现、合成验证
  5. 05 →

    Build Plan

    在固定输入与锁定运行环境下生成一致的计划字节，供下游执行，而不是让模型重新猜测布局。

    v2 Core / 新进程重复编译验证
  6. 06

    Blender / Unreal

    Blender 消费固定计划，保存后由独立进程重开检查。v2 Unreal 目前是数学坐标验证，真实引擎执行待验证。

    v2 Blender / 合成试点、审查未完成

模型提出候选。Scene Graph 记录接受的决策。Compiler 执行。
v2 的固定输入是 Scene Graph revision、Asset Manifest、Compile Policy 与 Compiler Version。确定性指锁定环境中相同输入得到一致 Build Plan，不是生成模型确定性，也不是跨平台字节一致性。

使用者最终能拿到什么？

结构化决策、来源链、编译诊断与执行计划。已演示的限定场景可在 Blender 检查、编辑和比较；v2 保存重开读取真实场景状态。自由编辑后的场景需要重新审查，不能继续把旧验证当作有效证明。完整真实资产到 Unreal 的交付链仍在建设中。

一个 Mesh，九次放置。
源支持与设计补全，各有依据。

这项实验回答的不是“能不能补满地板”，而是：什么时候允许补，补完后还能不能分清它为什么在那里？

问题

缺口不能靠外观升级成事实。

ST008–ST010 缺少足够源几何支持。补充图的相机注册仍有歧义，因此 Reconstruction 保留缺口；位置看起来合理不等于新增了独立观测。

证据

可信地板 prototype、已观测的 EVERY_1 重复规律、两端源支持板块、Station Graph，以及壳体 / 地面连续性和语义记录共同支持设计推断。

默认 allow_design_inference=false；本次只为地板组显式启用。prototype、pattern、结构连续性、空间上下文、语义支持与用户策略共同决定许可，条件不足仍为 deferred。

04 / 三种层次，三种含义

更完整，不等于更真实。

Source

模型提供的空间表示

Gaussian、PLY、Proxy 等源表示本身可能缺失或变形，是待评估证据，不是现实世界测量真值。

Reconstruction

当前规则下源支持的结果

保留有足够源支持的内容，也保留未知。Observed 表示源重建中有支持，不等于真实世界已实测验证。

Production

显式批准的设计补全

在重建基础上加入可追溯的生产选择。它可以更完整，但设计推断的几何权威不会因此提高。

Confidence 是证据支持程度；authority 是该来源被允许决定什么。高分不能替代来源权限，也不能替代接受记录。

05 / 第二案例 · 早期资产拟合实验

重建结果，不等于生产几何。

一个生成资产看起来合适，是否就能正确放回场景？椅子案例探索候选拟合与人工验收；地板案例验证决策与实例化，二者不是已贯通的自动流程。

画面中模糊的区域为保留的高斯场景参考层，用于辅助判断物体的空间位置、尺度与布局关系，并非最终生成的几何模型。随着独立 3D 资产逐步生成、验证并完成摆放，该参考层可随时一键隐藏，最终保留结构化、可编辑的 3D 场景。

01 / 参考裁切与独立参考

先明确要替代的对象。

从场景中的椅子开始，整理可供外形比对的参考。独立参考图补充了对象外观，但不直接提供真实尺寸、背面几何或世界坐标。

02 / 碎片重建与候选多视图

重建提供线索，候选提供另一种几何。

对照碎片化重建与生成资产，检查它们分别保留了什么、又缺少什么。这不是同一个模型的“修复前后”，也不能只凭外形完整就认定候选适合替代。

补充结构检查：靠背、座面、支撑与底座

03 / 分色结构检查

从“像一把椅子”，到检查各部位的关系。

分色帮助我查看不同部位的范围与连接关系，发现整体轮廓相似背后的局部差异。

自动语义分割、部件可编辑性与拓扑质量另需验证。

05 / 外观候选与场景回看

最后回到场景，而不是停在单个资产上。

重新拟合后，90.7% 的留出表面样本落在 0.05 个源单位以内，位置、朝向和统一缩放检查通过。作者经人工检查认为达到可替换标准，并接受原位替换。

日志同时记录了验收阈值的人工调整，以及仍存在的局部靠背与视线深度差异。这里保留此前未批准的诊断状态与后续场景回看，区分拟合指标和个案人工接受。

次级实验 / WorldSculpt：从碎片输出到连续表面的诊断

早期 GLB 虽然能正常读取，却由大量不连通碎片组成。我的排查定位到权重 key mismatch，修复采用运行时键重映射与严格加载守卫；外部重建模型来自 WorldSculpt。修复实验得到更连续的表面，但仍有薄片、裂缝与残留碎片。

WorldSculpt 是已封存的专项实验分支，未接入默认主流程。密集重建可以提供几何证据，但计算成本、薄结构、拓扑、UV 与生产材质仍限制其直接用于实时资产生产。

06 / 我的实现、证据与当前边界

从实验观察，
到可以审查的实现。

早期案例说明为什么需要这个系统；v2 重建用更明确的数据契约验证如何执行。两者的测试数量、数据与能力分别记录。

我的具体工作

  • 设计场景证据、候选提案与接受决策的分离流程，实现版本化记录、字段级采纳和来源 / 资产检查。
  • 编写 Python 编译与验证原型，把固定场景状态转换成 Build Plan；处理单位、坐标、pivot、层级与 stable ID。
  • 早期实验中诊断重建缺失与资产拟合，建立 prototype / pattern / Station Graph 与显式设计补全规则。
  • 实现 Blender 消费、保存、新进程重开与独立 readback 检查；记录失败、环境阻塞和未运行项。

外部模型与工具：Astra 用于理解与候选构建，Marble 提供重建源表示，Tripo / Hyper3D 提供生成资产，WorldSculpt 提供专项重建模型；Blender / Unreal 是下游工具。我的工作是流程、数据契约、诊断、规则、集成与验证。

历史空间查询 / Gaussian 与像素到 XYZ 的证据

50 万 Gaussian splats 是该早期数据集的规模。20 个查询点中，17 个得到支持，3 个返回 unsupported；它不是场景准确率。

距离为源单位，遮挡、相机不确定性、深度歧义与背面缺失仍需处理。

WORLDIR × MATE / 集成方向

场景决策，连接资产表面迭代。

WORLDIR 组织场景需要什么、依据是什么；MATE 支持资产审核、材质绑定与可编辑表面迭代。它们目前是独立原型，自动需求交接和场景回流仍是集成方向。
