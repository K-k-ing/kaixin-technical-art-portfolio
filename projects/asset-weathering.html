Overview

This self-initiated Technical Art R&D project explores a reusable workflow for generating initial weathering data from a game asset’s geometry and material properties. The pipeline produces UV-space wear, rust, and dirt masks in Blender, then uses those masks to drive adjustable real-time weathering in Unreal Engine 5.

AI assisted the upstream asset-development context; the current weathering system itself is based on explainable geometry analysis, exported masks, and artist-controlled material parameters.

Problem

While working with AI-assisted 3D assets, I found that generated models still required significant manual material work before they could be used in a real-time engine. Surface wear, oxidation, and dirt often had to be painted repeatedly, and the final result was difficult to adjust consistently across multiple assets.

Research Question

How could I generate a reusable first-pass weathering distribution from the asset itself, while keeping the final look editable inside the game engine?

Design Goals

  • Generate reusable first-pass weathering masks from mesh data
  • Keep the output editable in Substance, Blender, or a real-time engine
  • Allow artists to control weathering intensity without regenerating textures
  • Build a transparent and explainable pipeline rather than a black-box result

Pipeline Overview

The workflow separates geometry analysis, UV-space data generation, and final look development so each stage remains inspectable and adjustable.

  1. 01

    Game Asset

    An existing mesh and material set provide the source data for the study.

  2. 02

    Mesh and UV Validation

    The current version checks that a usable mesh and UV map already exist.

  3. 03

    Geometry and Material Analysis

    Curvature, normal variation, metal regions, AO, and cavity signals are evaluated.

  4. 04

    UV-Space Mask Generation

    Per-vertex weights are interpolated across UV triangles to build grayscale masks.

  5. 05

    PNG Export

    WearMask, RustMask, and DirtMask are exported as reusable texture data.

  6. 06

    UE5 Master Material

    The exported masks drive surface blending inside M_AI_Weathering.

  7. 07

    Real-Time Control

    Material Instance parameters adjust wear, rust, and dirt without replacing the mesh.

Blender Python Pipeline

The Blender stage generates a first-pass distribution from measurable mesh signals. It does not attempt to infer environmental meaning.

01 / WEAR

Wear Mask

Generated from curvature and normal variation to identify exposed edges and structural transitions.

02 / RUST

Rust Mask

Combines metal-region information with AO and cavity signals to restrict oxidation to plausible metallic and occluded areas.

03 / DIRT

Dirt Mask

Uses AO and cavity information to identify recessed, connected, and locally occluded regions.

UV-Space Generation

The generated values become portable texture data that can be inspected and refined outside the analysis script.

01

Interpolate

Per-vertex analysis weights are interpolated inside each UV triangle.

02

Rasterize

Each signal is written as a grayscale mask within the 0–1 UV tile.

03

Pad

Configurable padding and dilation extend values beyond UV island borders.

Padding reduces sampling artifacts around UV islands, but complex mirrored, overlapping, or cross-island continuity remains an area for further development. The current version requires an existing valid UV map and does not include automatic unwrapping or UDIM support.

Unreal Engine Material System

The material converts reusable masks into non-destructive surface states controlled through a Material Instance.

The UE5 material keeps the weathering result non-destructive. The same mesh and master material can produce multiple asset states by changing instance parameters rather than replacing the entire texture set.

Results

The prototype established a validated Blender-to-Unreal loop: geometry-derived masks were generated, exported into UV space, and consumed by a parameterized real-time material.

RAPID PROTOTYPING

Rapid Prototype Validation

The core prototype was validated during a focused one-day development sprint. Within that period, I established the Blender mask-generation workflow, exported UV-space textures, built the UE5 master material, and tested clean-to-weathered transitions on the AI Pilgrim Head asset.

This rapid iteration helped me focus on technical direction, debugging, and cross-software integration before expanding the feature scope.

Challenges and Decisions

Each decision keeps a technically useful first pass while preserving artist control and documenting the current limitations.

01

UV island boundaries and sampling artifacts

Decision: Use configurable padding and dilation while clearly documenting remaining seam limitations.

02

Procedural masks can look technically correct but visually uniform

Decision: Separate Wear, Rust, and Dirt signals so artists can tune or repaint them independently.

03

A baked final texture is difficult to iterate in-engine

Decision: Use generated masks as reusable data and perform final blending in a UE5 master material.
