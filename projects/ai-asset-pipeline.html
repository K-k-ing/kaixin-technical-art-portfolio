01 / 项目背景与规划验证

模型需要的不是更多面，
而是合适的面数。

在使用 AI 制作 3D 资产的过程中，我发现更高的目标面数并不总能得到更好的生成结果。对于以平面、折线和明确轮廓为主的简单资产，增加几何也可能引入多余起伏和不稳定的表面结构。

我用金属五角星进行测试：左图是经过预算计算后生成的约 500 面版本，右图为 2,000+ 面版本。在这组结果中，规划后的低面数版本主要折面与轮廓更清楚，视觉表现反而更好。

展开线框与实际统计：503 / 2,056 面片

这个案例支持我在生成前按结构需求规划预算，而不是默认选择高密度输出；它不单独证明“面数越少，质量越高”。原截图统计口径为“面片”，后续工具与验证统一使用 Triangles，不直接混算。

02 / 工具目标

在生成之前，先回答三个制作问题。

从哪里开始？

选择候选面数

这个资产应该从多少三角面开始尝试，而不是默认选择最高密度？

把面用在哪里？

区分几何与贴图

哪些结构需要真实几何，哪些细节可以交给贴图、法线与材质？

如何判断合适？

结合使用条件

在资产用途、观看距离与目标平台下，应该优先测试哪个档位？

我希望把依赖经验的参数选择，转化为一个可以查看依据、调整条件和检查结果的工作流。

04 / 已实现功能

数字之外，让结构判断也能被检查。

参考图输入与预览

支持点击与拖拽上传、图片预览、尺寸和大小校验，以及重置、失败提示和重试。

真实 AI 结构分析

多模态视觉服务分析轮廓、平面／曲面、薄结构、小型细节、对称重复与遮挡不确定性，整理为 GeometryImageAnalysisV1 数据。

可解释的三档规划

本地 TypeScript 计算器结合结构特征和使用条件，输出最低成形候选、平衡预算与高预算测试值。

分析来源与运行状态

显示后端连接、Mock / Real AI 模式、模型与分析来源。真实调用失败时不静默返回 Mock 示例，避免把演示数据当作真实分析。

Geometry vs Texture

顶部圆环、鞋尖与铃铛等空间结构需要考虑几何支撑；菱形拼色、浅表缝线阴影与材质高光则可能通过贴图或法线表达。

结果不只给出面数，还解释哪些细节值得占用几何预算，让我能检查“看起来复杂”是否真的意味着“需要更多几何”。

05 / 当前结果示例 · 鞋子配件

同一份结构分析，给出三个验证起点。

这次输入为一双带装饰的幻想风格鞋子，界面条件为“标准游戏道具 / 近距离 / 影视级”。以下数字仅对应本次参考图与条件。

推荐区间 / Triangles2,100–4,500

预算规划输出，不是生成后的网格统计。

Minimum / 最低成形候选2,050

优先检查轮廓、尖角与薄结构。

Balanced / 平衡目标3,300

选择结构保持与几何成本的起始目标。

High / 高预算测试4,500

验证增加面数是否带来真实细节收益。

未知的结构，也需要被明确记录。

单张参考图无法确认鞋子背面、相互遮挡处，以及铃铛与鞋尖的连接方式。界面保留这些不确定性，并说明它们如何影响测试区间。

相应建议还需要通过实际生成、导出网格统计与美术观察验证，不能只靠页面中的一组数字判断成功。

这组预算不是所有类似资产的通用标准，也不是下方完整角色模型的实际面数。鞋子分析和完整角色测试分开展示，不把它们排成未经说明的一对一生成结果。

06 / 从预算建议到实际建模

进入真实建模，再观察造型与线框。

我将规划建议用于后续 AI 建模，检查生成资产的外轮廓、主要体块与线框分布。当前测试已经得到能够保持主要造型、同时控制几何规模的结果。

独立对照资料 / 非本人制作

游戏资产面数规模对照

在我目前测试的案例中，规划后生成资产的面数规模已接近用于对照的《马里奥赛车8》模型。这个比较关注几何预算规模，不代表整体制作质量、拓扑质量或蒙皮与动画变形能力相同。

当前线框截图没有显示完整统计数字，因此暂不填写具体减面百分比，也不把两者视为同类、同条件的严格性能测试。

对照来源：《马里奥赛车8》角色模型线框资料。原作及角色版权归 Nintendo；仅用于学习与几何规模观察。

07 / 关键技术设计

让 AI 理解结构，
让规则负责数字决策。

我没有让视觉模型直接给出一个无法追溯的面数，而是把理解与计算拆成两个部分。

视觉层

参考图 → 结构化理解

轮廓、曲面、薄结构、装饰细节与不确定性。

→
规则层

特征 + 条件 → 预算

本地确定性计算，给出候选区间与解释。

→
验证层

生成资产 → 检查与修正规则

记录实际三角面，观察几何、法线与贴图质量。

相同的结构化输入可以得到相同计算结果，方便追溯推荐依据与调整规则。确定性不等于准确性，但它为准确性的验证和改进提供了基础。

统一三角面口径

使用 Triangles，避免 Faces、Polygons 和 Vertices 混用。后续以实际导出网格比较，而不是直接采用生成器滑块的目标值。

适配器隔离

视觉服务放在独立适配器中，区分 Mock 与真实调用，减少供应商变化对前端和预算计算器的影响。

数据与密钥边界

返回结果经过 JSON 提取、运行时验证与归一化后才进入计算器。API 密钥只由后端读取，不向前端返回，也不记入请求日志。

08 / 遇到的挑战与解决过程

从分层诊断，到可验证的预算选择。

从笼统报错到分层诊断；从视觉复杂度到几何／贴图分工；在低面数与造型保持之间寻找合适预算。

挑战一

分析失败，但界面只显示 Failed to fetch

问题

图片能够正常预览，点击分析后却无法获得结果，错误信息不足以定位原因。

原因

排查发现开发进程因端口冲突退出，导致本地请求链路中断。

解决

  • 处理端口冲突，统一监听地址；
  • 修正前后端代理目标，使用相对 API 路径；
  • 增加健康检查与状态接口；
  • 将笼统错误改为分层提示。

收获前端可打开、本地后端可访问、远程模型可调用，是三个不同状态，必须分别显示和检查。

挑战二

视觉细节不等于几何复杂度

问题

高光、图案、阴影和浅表纹理可能让图片显得复杂。如果直接把这些信息转换为几何需求，预算就容易偏高。

解决

在分析中显式区分：

  • 影响轮廓和空间结构的细节；
  • 可由贴图、法线与材质表达的细节；
  • 单视图无法确认的结构。

结果界面同时展示几何与贴图建议，让使用者能够检查 AI 的判断是否合理。

收获面数规划首先是结构判断问题，而不是数字预测问题。

挑战三

既要低面数，也要保持造型

问题

一味降低预算可能破坏曲面、尖角和小型附件；一味提高预算也不能保证生成更正确。

解决

提供最低、平衡和高预算三档，支持从候选值出发，通过实际生成检查逐步选择。

同时引入资产用途、观看距离和平台条件，使推荐不再只依赖物体类别。

收获工具的目标不是追求最小数字，而是在可接受视觉表现下控制几何成本。

从分析界面，推进到实际建模应用。

10 / 项目价值与后续方向

让预算成为有依据的起点，
而不是一个确定的答案。

发现生成结果差异 → 提出预算假设 → 建立分析和规则系统 → 应用于建模 → 检查结果。这条路径把面数选择从单纯试错，转化为有结构依据的起始建议。

记录可比较的数据

同时记录目标面数与实际三角面数，对相同参考图进行多档、重复生成。

分开验收不同质量

统一视角和显示条件，分别检查几何、法线与贴图，不让一个总面数掩盖具体问题。

继续验证泛化

使用未参与规则调整的资产验证表现，为不同生成器与版本积累独立的预算经验。

03

资产拆分

将复杂资产拆分为较小组件，以提高生成准确性、简化检查，并支持独立替换与优化。

为什么要拆分资产？

飞船被拆分为主体、环形结构、机翼、着陆支架、机械关节、连接件与次级细节。角色和机器人也采用同样逻辑，分别处理头部、躯干、手臂、机械骨架、装甲与功能附件。

04

Blender 清理与优化

将整模生成中模糊、不稳定或结构不一致的部分单独提取，分别重新生成。

这种方式改善了局部轮廓准确性、机械关节辨识度、组件替换、细节控制与组装灵活性。

  1. 01

    整体生成检查

    检查组装结果并识别不稳定区域。

  2. 02

    独立组件

    从整体生成结果中分离问题区域。

  3. 03

    细化组件

    重新生成或替换为结构更清晰的组件。

  4. 04

    最终组装

    将细化组件重新整合，并复查完整资产。

08

Blender 检查与组装

在 Blender 中检查生成资产的比例、组件关系、结构完整性、材质显示、厚度与导入可用性。

用单独生成的组件替换质量较低或不稳定的部件，再重新整理、缩放和组装模块，形成更完整的资产用于 Unreal Engine 验证。

  • 尺度与比例
  • 部件对齐
  • 几何完整性
  • 厚度
  • 表面质量
  • 材质插槽
  • 组件层级
  • 导入准备情况

06

研究发现与局限

这套流程适用于原型制作，但生成结果仍需要细致的技术与美术检查。

01

薄片几何

较薄的机翼、面板与机械结构在生成时可能塌陷，或失去清晰形态。

02

高细节变形

增加模型复杂度可能带来比例不稳定、表面噪点与组件扭曲。

03

拓扑质量

生成网格在组装前经常需要手工检查、清理或替换。

04

组件一致性

单独生成的部件可能在尺度、连接点或视觉语言上不一致。

05

材质转换

粗糙度、反射表面、透明度与分层磨损并不总能可靠地传递。

06

参考素材准备

干净、独立且针对目标制作的参考，通常优于直接裁切复杂概念图。

07

跨资产一致性

在角色、载具、道具与场景之间维持统一视觉语言仍有难度。

这个项目加深了我对模块化资产规划、参考素材准备、AI 生成局限、Blender 检查、场景组装与 Unreal Engine 验证的理解。

实践中更可靠的方式，是让 AI 生成、美术判断、模块化设计与实时测试相互配合，形成可控的制作过程。
