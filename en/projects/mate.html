02 / Personal project · Technical art tool

MATEAI-Assisted Material Analysis & Procedural Weathering

Material Analysis & Texture Editor

Keep materials editable after generation.

When working with AI-generated models, I found that materials and textures often felt unpredictable. Adjusting a particular surface or region to match an artistic intention was difficult. I built MATE to explore a more controllable post-generation workflow.

MATE connects multi-view analysis, human review, real model targets, and an editable effect stack. It turns AI's interpretation of a model into operations an artist can inspect, adjust, and compare.

01 / Starting point

AI sees different surfaces.
The model may have only one material slot.

An aircraft test asset made the problem concrete: white paint, glass, sensor housings, and decals looked like separate regions, but shared one material slot. Recognizing them did not tell me how to edit them independently.

I focused on what happens after analysis. The user needs to confirm three things: the intended material, the actual target it affects, and whether the available data supports the operation.

MATE is for 3D artists and technical art learners who want to keep editing an existing GLB asset. AI provides a starting proposal; the user retains the final say on intent and appearance.

01

Reviewable proposals

Normalize terminology and parameters before asking for confirmation. Natural language is not an execution command.

02

Inspectable scope

Make the relationship between regions, model targets, UVs, and masks explicit. A visual label alone is not enough.

03

Repeatable adjustment

Edit parameters, toggle layers, and compare with the original asset within the same editing session.

02 / Workflow

A clear input and next step at every stage.

I follow a familiar art-production sequence, placing review, binding, and preflight checks where they become relevant.

03 / Three core capabilities

From understanding a surface to controlling it.

01

AI material analysis,
with review built in.

Multiple views help Qwen interpret regions and appearance. Rather than executing its output directly, I normalize terminology, validate the structure, and move it into an editable material profile.

The user can review categories, edit color, roughness, metallic response, and texture intent, then confirm what should happen next.

The AI capability integrates an external model; it is not a proprietary model I trained. Analysis confidence is not recognition accuracy.

View the actual proposal review interface
02

Confirm where to edit,
then decide how.

I bind semantic regions to real model material slots. When several regions share one slot, surface masks restrict the local scope, with UV checks before local processing.

Candidate masks must be previewed, checked, and accepted. The interface keeps uncertainty visible so that incorrect assignments can be found.

This test exposes a current failure: the Propeller Hub region receives 92.0% of the surface, while White Composite Body receives 0.0%. The reported 95.4% is assigned coverage, not segmentation accuracy.

03

Iterate with an effect stack,
not just a result image.

Paint chipping and dust are separate effects that can be added, removed, enabled, and adjusted. Coverage, patch size, breakup, and placement rules control different aspects of the surface.

Exposed substrate color, roughness, and metallic response are also adjustable. Switching between the original and MATE preview helps reveal what each layer changes.

This case study focuses on the recorded paint-chipping and dust workflows. Other effects remain in development and are not presented as equally mature.

04 / Material control after generation

Keep shaping the material you already have.

My focus is not another generation attempt. It is how to keep adjusting an existing model toward the result I want.

Treated previewOriginal preview

Two actual screenshots of the same asset, centered at their original aspect ratios. This is a screenshot comparison, not real-time rendering inside the website.

“Less chipping, but keep the large patches.”

Adjust coverage separately from scale, so reducing the affected area does not also change the patch shape.

“Add dust without losing the substrate response.”

Adjust the effect layer and exposed material separately, observing color alongside roughness and metallic response.

“What is this layer actually contributing?”

Toggle chipping or dust independently, then compare with the original asset. The current session retains the relationships between effects.

Adjusting the existing procedural preview does not require a new AI analysis call each time; initial analysis still uses an external model. Full project saving and restoring effect stacks across sessions are not currently verified capabilities.

Manifest · Available targets

Execution gates · Can this proceed?

UV preflight, mask acceptance, versions, and stale states jointly control subsequent operations.

Materials change; targets remain stable.

Target identity uses glTF source indices and scene context. The slot ID does not include the current material index, so replacing a material does not change the attachment point.

slot:s0:n0:m0:p0

Illustrative ID: scene / node / mesh / primitive define the material slot.

Old results must not overwrite a new asset.

Worker tasks carry asset and binding versions, task identity, and cancellation signals. After an asset or binding change, late results must revalidate their context; invalid results are explicitly marked stale.

“Indeterminate” is a valid state, not an implicit pass.

06 / Challenges & solutions

Engineering the workflow, checking the image.

Development involved data structure, tool interaction, and visual quality. Each challenge below records the problem, my decision, and the current boundary—including what remains unresolved.

01

How does AI interpretation become executable data?

Data boundaries

ProblemTerms such as “painted” or “metal” do not necessarily map to internal categories and parameters.

DecisionI added terminology normalization, structured validation, and human review before execution, allowing the user to resolve ambiguity and confirm a material profile.

Result and limitA proposal-to-review workflow is in place. Analysis can still be wrong, so review is part of the design, not a temporary workaround.

02

What if several semantic regions share one material slot?

Region control

ProblemEditing the shared slot affects surfaces that should be treated independently.

DecisionI manage asset structure, runtime mapping, and region binding separately, distinguishing whole-slot edits from local mask processing.

Result and limitThe binding and candidate-mask workflow is established. The assignment error in the screenshot shows why a correct binding does not imply accurate pixel segmentation; human review is still required.

03

How can the same target survive complex structures and material replacement?

Stable identity

ProblemShared meshes, multiple primitives, repeated instances, and duplicate node names make names or runtime UUIDs insufficient as source identities.

DecisionUse glTF source indices and scene context, validate source-to-runtime mappings, and leave the material index out of slot identity.

Result and limitDevelopment checks cover references, instances, mappings, and lifecycle behavior. They support this design, not a guarantee of compatibility with every asset.

04

Why can local processing fail even when UV0 exists?

UV preflight

ProblemUVs can exist while overlapping, extending out of range, or containing degenerate triangles. Resolution and compute budgets also affect the conclusion.

DecisionRun preflight checks in a Worker, deduplicate shared-slot checks, and report pass, blocked, or indeterminate states with reasons and conditions.

Result and limitPreflight status now gates execution. It detects and blocks problematic input; it does not automatically repair or unwrap UVs.

05

How can high-polygon assets avoid repeated computation?

Shared data

ProblemWhen instances reference the same geometry, scanning it once per slot multiplies the work.

DecisionReuse geometry checks, cache shared attributes and existing bounds, inspect unique material slots, and use Workers and compute budgets for heavy tasks.

Result and limitDevelopment records include import, multi-view capture, and analysis checks on an asset of approximately 1.9 million triangles. Full real-time weathering frame rate, memory use, and end-to-end timing still need systematic measurement.

06

How can late asynchronous results avoid affecting the current asset?

Lifecycle

ProblemEarlier tasks can return after an asset change, binding edit, or interface closure.

DecisionInclude versions, task identity, cancellation, and lifecycle checks in the workflow. Clear invalid mappings and do not use stale results as execution evidence.

Result and limitRegression checks cover cancellation, late results, retry, and unmounting. Further validation focuses on state transitions during actual editing.

07

How can weathering preserve lettering, decals, and panel lines?

Source fidelity

ProblemTest assets mix lettering, decorative lines, and some shading into BaseColor. Replacing the base color can weaken all of them.

DecisionAdd an original-coating detail-preservation control, and test both complete PBR assets and BaseColor-only inputs for quality and compatibility.

Result and limitPreservation controls are still being refined, with fine lines and decals checked case by case. A single BaseColor image cannot establish reliable recovery of real geometry or a complete physical material.

08

Why does stronger noise not necessarily look more natural?

Shape hierarchy

ProblemEarly paint chipping produced large, cloudy patches with weak edge hierarchy and insufficient close-up detail.

DecisionTreat distribution, scale, edges, and material response separately. Introduce multiple scales, structural influence, and substrate response, then evaluate close-up views.

Result and limitControls and implementation have progressed. Secondary broken edges, micro-notches, seam dirt, and rust interactions remain next steps; an available control is not proof of final visual quality.

09

Does a passing build mean the image is ready?

Validation

ProblemType checks, regression tests, and successful builds cannot prove that chipping looks natural or materials look convincing.

DecisionSeparate engineering checks from visual acceptance. Compare wide, medium, and close views under fixed cameras and lighting, using evidence appropriate to each goal.

Result and limitThis first version demonstrates the tool workflow. Material naturalness, final output, and performance each require their own validation and guide the next iterations.

09 / Iteration & next steps

The workflow works. Visual quality and output come next.

Close-up views make the shortcomings clearer. These actual details are retained as evidence for the next iteration, not presented as final-quality results.

Demonstrated

An operable material prototype

GLB import, multi-view analysis, review and configuration, region binding, UV and candidate-mask workflows, paint-chipping and dust previews, and saved output presets.

Further validation

Local quality and applicability

Candidate-mask quality, source-coating fidelity, close-up shapes, and rust interaction. Measure preview performance across assets without generalizing efficiency from a single example.

Not yet complete

Actual texture output

Texture baking, PBR map output, and asset packaging. Current resolution, format, and channel options are saved settings—not evidence of a finished export.

For me, MATE's first milestone is moving from “AI says this is a material” to “I know where it acts, and I can keep adjusting it.” More rigorous visual comparisons and output validation will guide the next version.
